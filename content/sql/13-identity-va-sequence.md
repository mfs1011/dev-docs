Ko'p jadvallarda har qatorga avtomatik **tartib raqami** kerak bo'ladi: mijoz №1, mijoz №2, … Bu raqamni ilova o'zi hisoblamaydi, uni baza beradi. SQL'da buning uchun ikki tushuncha bor:

- **Sequence** (ketma-ketlik) — raqamlar beradigan alohida obyekt. Har murojaatda keyingi sonni qaytaradi.
- **Identity ustun** — qiymati yashirin sequence'dan avtomatik olinadigan ustun.

### Identity ustun

PostgreSQL hujjatiga ko'ra identity ustun — yashirin sequence'dan avtomatik to'ldiriladigan maxsus ustun. U kalit qiymatlarini yaratish uchun ishlatiladi:

```sql
CREATE TABLE people (
    id bigint GENERATED ALWAYS AS IDENTITY,
    ...
);
-- yoki
CREATE TABLE people (
    id bigint GENERATED BY DEFAULT AS IDENTITY,
    ...
);
```

`INSERT` da ustunga qiymat berilmasa, sequence'dagi keyingi raqam yoziladi. Aynan shu raqamni `DEFAULT` kalit so'zi bilan ham so'rash mumkin. Hujjatga ko'ra "ko'p jihatdan identity ustun sukut bo'yicha qiymatli ustunga o'xshaydi".

Ikki variantning farqi foydalanuvchi o'zi qiymat yozganda bilinadi:

| Variant | Foydalanuvchi qiymat yozsa |
| --- | --- |
| `GENERATED ALWAYS` | Rad etiladi. Faqat `INSERT … OVERRIDING SYSTEM VALUE` bilan qabul qilinadi. Hujjatga ko'ra bu tasodifan qiymat yozib qo'yishdan ko'proq himoya qiladi |
| `GENERATED BY DEFAULT` | Foydalanuvchi qiymati ustun turadi. Oddiy `DEFAULT` ga o'xshaydi |

Hujjatdagi yana ikki muhim qoida:

- identity ustun avtomatik `NOT NULL` bo'ladi;
- lekin u **yagonalikni kafolatlamaydi**. Sequence odatda takrorlanmas qiymat beradi, lekin uni qayta o'rnatish yoki ustunga qo'lda qiymat yozish mumkin. Yagonalik `PRIMARY KEY` yoki `UNIQUE` cheklovi bilan ta'minlanadi (14-bob).

### `serial` — eski usul

`serial` (`smallserial`, `bigserial`) PostgreSQL'ga xos yozuv. Hujjatga ko'ra ular "haqiqiy tiplar emas, faqat qulay qisqartma". `id serial` aslida uchta buyruqqa teng:

```sql
CREATE SEQUENCE tablename_colname_seq AS integer;
CREATE TABLE tablename (
    colname integer NOT NULL DEFAULT nextval('tablename_colname_seq')
);
ALTER SEQUENCE tablename_colname_seq OWNED BY tablename.colname;
```

Hujjat `serial` ni "PostgreSQL'ga xos usul" deb ataydi. **Standartga mos** yo'l esa identity ustun.

### Sequence

Sequence — bitta qatorli maxsus jadval. U `nextval`, `currval`, `setval` funksiyalari bilan boshqariladi:

| Funksiya | Vazifasi |
| --- | --- |
| `nextval('s')` | Keyingi qiymatni oladi. Bu **atomar**: bir vaqtda ko'p seans chaqirsa ham, har biri har xil son oladi |
| `currval('s')` | **Shu seansda** `nextval` qaytargan oxirgi qiymat. Boshqa seanslar unga ta'sir qilmaydi |
| `setval('s', n)` | Joriy qiymatni o'rnatadi |

Standartdan farq: keyingi qiymat standartdagi `NEXT VALUE FOR` emas, `nextval()` bilan olinadi. `OWNED BY` ham PostgreSQL kengaytmasi.

### Bo'shliqlar muqarrar

Hujjat bu haqida ochiq ogohlantiradi. `nextval` olgan qiymat tranzaksiya bekor qilinsa ham **qaytarib olinmaydi**. Aks holda bir xil sequence'dan raqam olayotgan boshqa tranzaksiyalarni kutib turish kerak bo'lardi. Natijada:

- bekor qilingan tranzaksiya yoki server ishdan chiqishi raqamlar orasida **bo'shliq** qoldiradi;
- bekor qilishsiz ham bo'shliq paydo bo'lishi mumkin. Masalan, `ON CONFLICT` li `INSERT` qiymatni konflikt aniqlanishidan **oldin** oladi;
- `CACHE` 1 dan katta bo'lsa, seans oldindan olgan, lekin ishlatmagan qiymatlar seans tugaganda yo'qoladi. Turli seanslarning qiymatlari esa qat'iy o'sish tartibida bo'lmasligi mumkin.

Hujjatning xulosasi: sequence'lardan "**bo'shliqsiz**" raqamlash uchun foydalanib **bo'lmaydi**. Masalan, buxgalteriyadagi ketma-ket hujjat raqamlari uchun. Buni hisoblagich jadvalini eksklyuziv qulflab qilish mumkin, lekin bu "ancha qimmat" (54-bob).

### `GENERATED ALWAYS`

```sql
CREATE TABLE mijozlar (
    id  bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    ism text NOT NULL
);
INSERT INTO mijozlar (ism) VALUES ('Ali'), ('Vali');
INSERT INTO mijozlar (id, ism) VALUES (10, 'Sobir');
```

```text
INSERT 0 2
ERROR:  cannot insert a non-DEFAULT value into column "id"
DETAIL:  Column "id" is an identity column defined as GENERATED ALWAYS.
HINT:  Use OVERRIDING SYSTEM VALUE to override.
```

Qo'lda yozilgan qiymat rad etildi. Ataylab kerak bo'lsa:

```sql
INSERT INTO mijozlar (id, ism) OVERRIDING SYSTEM VALUE VALUES (10, 'Sobir');
INSERT INTO mijozlar (id, ism) VALUES (DEFAULT, 'Dilnoza');
SELECT * FROM mijozlar ORDER BY id;
```

```text
 id |   ism   
----+---------
  1 | Ali
  2 | Vali
  3 | Dilnoza
 10 | Sobir
(4 rows)
```

`Sobir` ga qo'lda 10 berildi, lekin sequence bundan "xabar topmadi" va keyingi qiymat 3 bo'ldi.

### `GENERATED BY DEFAULT` va to'qnashuv

`BY DEFAULT` da qo'lda qiymat yozish oson. Lekin sequence keyin aynan shu qiymatga yetib keladi:

```sql
CREATE TABLE m (id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, ism text);
INSERT INTO m (ism) VALUES ('Ali');
INSERT INTO m (id, ism) VALUES (2, 'qolda');
INSERT INTO m (ism) VALUES ('Vali');
INSERT INTO m (ism) VALUES ('Vali');
SELECT * FROM m ORDER BY id;
```

```text
INSERT 0 1
INSERT 0 1
ERROR:  duplicate key value violates unique constraint "m_pkey"
DETAIL:  Key (id)=(2) already exists.
INSERT 0 1
 id |  ism  
----+-------
  1 | Ali
  2 | qolda
  3 | Vali
(3 rows)
```

Sequence 2 ni berdi, u esa band edi. Xatoni `PRIMARY KEY` ushladi. Usiz jadvalda ikkita `id = 2` paydo bo'lardi. Hujjatdagi "identity yagonalikni kafolatlamaydi" degan gapning ma'nosi shu. Xatolik bilan tugagan `INSERT` ham bitta raqamni "yeb" qo'ydi: navbatdagi `Vali` 3 ni oldi.

PRIMARY KEY bo'lmagan `BY DEFAULT` ustunida esa takror jimgina o'tib ketadi:

```sql
CREATE TABLE buyurtmalar (id integer GENERATED BY DEFAULT AS IDENTITY, izoh text);
INSERT INTO buyurtmalar (izoh) VALUES ('a');
INSERT INTO buyurtmalar (id, izoh) VALUES (2, 'qo''lda');
INSERT INTO buyurtmalar (izoh) VALUES ('b');
SELECT * FROM buyurtmalar ORDER BY id;
```

```text
 id |  izoh  
----+--------
  1 | a
  2 | qo'lda
  2 | b
(3 rows)
```

### Bekor qilingan tranzaksiya bo'shliq qoldiradi

```sql
BEGIN;
INSERT INTO mijozlar (ism) VALUES ('Bekor');
ROLLBACK;
INSERT INTO mijozlar (ism) VALUES ('Keyingi');
SELECT id, ism FROM mijozlar ORDER BY id;
```

```text
 id |   ism   
----+---------
  1 | Ali
  2 | Vali
  3 | Dilnoza
  5 | Keyingi
 10 | Sobir
(5 rows)
```

`Bekor` qatori saqlanmadi, lekin 4-raqam "sarflandi". `Keyingi` 5 ni oldi.

### Identity ortidagi sequence

```sql
SELECT pg_get_serial_sequence('mijozlar', 'id') AS sequence;
```

```text
        sequence        
------------------------
 public.mijozlar_id_seq
(1 row)
```

### `serial`

```sql
CREATE TABLE eski (id serial, nom text);
\d eski
```

```text
                            Table "public.eski"
 Column |  Type   | Collation | Nullable |             Default              
--------+---------+-----------+----------+----------------------------------
 id     | integer |           | not null | nextval('eski_id_seq'::regclass)
 nom    | text    |           |          | 
```

`serial` degan tip yo'q: ustun `integer`, sukut bo'yicha qiymat esa `nextval(…)`. Hujjatda aytilganidek.

### Mustaqil sequence

```sql
CREATE SEQUENCE chek_raqami START 1000 INCREMENT 10;
SELECT nextval('chek_raqami'), nextval('chek_raqami'), currval('chek_raqami');
SELECT setval('chek_raqami', 5000), nextval('chek_raqami');
```

```text
 nextval | nextval | currval 
---------+---------+---------
    1000 |    1010 |    1010
(1 row)

 setval | nextval 
--------+---------
   5000 |    5010
(1 row)
```

### MySQL: `AUTO_INCREMENT`

MySQL'da identity va sequence yo'q. Ularning o'rnida ustun atributi `AUTO_INCREMENT` bor. MySQL hujjatidagi qoidalar:

- qiymat berilmasa, avtomatik raqam beriladi;
- `0` yoki `NULL` yozilsa ham avtomatik raqam beriladi. `0` uchun istisno — `NO_AUTO_VALUE_ON_ZERO` rejimi yoqilgan bo'lsa;
- **boshqa qiymat** yozilsa, u saqlanadi va hisoblagich **eng katta qiymatdan keyinga** suriladi. PostgreSQL identity'sidan asosiy farq shu;
- oxirgi avtomatik qiymatni `LAST_INSERT_ID()` beradi. Bu **ulanishga tegishli**: boshqa ulanishlarning `INSERT` lari unga ta'sir qilmaydi.

```sql
CREATE TABLE mijozlar (id INT NOT NULL AUTO_INCREMENT PRIMARY KEY, ism VARCHAR(30) NOT NULL);
INSERT INTO mijozlar (ism) VALUES ('Ali'), ('Vali');
SELECT LAST_INSERT_ID();
INSERT INTO mijozlar (id, ism) VALUES (0, 'Nol'), (NULL, 'Null');
INSERT INTO mijozlar (id, ism) VALUES (100, 'Sobir');
INSERT INTO mijozlar (ism) VALUES ('Keyingi');
START TRANSACTION;
INSERT INTO mijozlar (ism) VALUES ('Bekor');
ROLLBACK;
INSERT INTO mijozlar (ism) VALUES ('Oxirgi');
SELECT * FROM mijozlar ORDER BY id;
```

```text
+------------------+
| LAST_INSERT_ID() |
+------------------+
|                1 |
+------------------+
+-----+---------+
| id  | ism     |
+-----+---------+
|   1 | Ali     |
|   2 | Vali    |
|   3 | Nol     |
|   4 | Null    |
| 100 | Sobir   |
| 101 | Keyingi |
| 103 | Oxirgi  |
+-----+---------+
```

Bu natijada uchta narsa bor:

- Ikki qatorli `INSERT` dan keyin `LAST_INSERT_ID()` = **1**. Hujjatga ko'ra ko'p qatorli `INSERT` da u **birinchi** yaratilgan qiymatni qaytaradi.
- `100` dan keyin `Keyingi` 101 ni oldi. Hisoblagich eng katta qiymatga ergashdi.
- Bekor qilingan tranzaksiya 102 ni "yeb" qo'ydi. Hujjatga ko'ra InnoDB'ning hamma qulf rejimlarida bekor qilingan qiymatlar "yo'qoladi" va qayta ishlatilmaydi.

```sql
INSERT INTO mijozlar (ism) VALUES ('A'), ('B'), ('C');
SELECT LAST_INSERT_ID() AS birinchisi, MAX(id) AS oxirgisi FROM mijozlar;
SELECT AUTO_INCREMENT FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'qollanma' AND TABLE_NAME = 'mijozlar';
```

```text
+------------+----------+
| birinchisi | oxirgisi |
+------------+----------+
|        104 |      106 |
+------------+----------+
+----------------+
| AUTO_INCREMENT |
+----------------+
|            107 |
+----------------+
```

**Qulf rejimi va bo'shliqlar.** `innodb_autoinc_lock_mode` MySQL 9.7 da sukut bo'yicha `2` ("interleaved"). Hujjatga ko'ra bu rejimda `INSERT … SELECT` kabi "ommaviy" yozuvlar bir vaqtda boshqa `INSERT` lar bilan bajarilsa, qiymatlar orasida bo'shliq qolishi mumkin.

```text
| @@innodb_autoinc_lock_mode |
|                          2 |
```

**Hisoblagich serverni qayta ishga tushirgandan keyin ham saqlanadi.** InnoDB uning eng katta qiymatini har o'zgarishda redo log'ga, har checkpoint'da ma'lumotlar lug'atiga yozadi.

**Tip chegarasi.** Hujjat yetarli eng kichik butun tipni tanlashni maslahat beradi. Chegaraga yetilganda keyingi raqam yaratish **muvaffaqiyatsiz** bo'ladi:

```sql
CREATE TABLE kichik (id TINYINT AUTO_INCREMENT PRIMARY KEY, x INT);
INSERT INTO kichik (id, x) VALUES (127, 1);
INSERT INTO kichik (x) VALUES (2);
```

```text
ERROR 1062 (23000) at line 18: Duplicate entry '127' for key 'kichik.PRIMARY'
```

**Cheklovlar.** Jadvalda bitta `AUTO_INCREMENT` ustun bo'ladi va u kalit bo'lishi shart:

```text
ERROR 1075 (42000) at line 19: Incorrect table definition; there can be only one auto column and it must be defined as a key
```

### SQLite: `rowid` va `AUTOINCREMENT`

SQLite hujjatining asosiy gapi:

> `AUTOINCREMENT` kalit so'zi qo'shimcha protsessor, xotira, disk va kiritish-chiqarish xarajati talab qiladi. Qat'iy kerak bo'lmasa, undan **qochish kerak**. Odatda u kerak emas.

Sababi shu. SQLite'da `INTEGER PRIMARY KEY` ustuni `rowid` ning **taxallusi** (12-bob). Qiymat berilmasa, u avtomatik to'ldiriladi: odatda hozirgi eng katta `rowid` + 1. Bu `AUTOINCREMENT` bo'lsa ham, bo'lmasa ham shunday ishlaydi.

`AUTOINCREMENT` faqat bitta narsani o'zgartiradi: o'chirilgan qatorlarning raqamlari **qayta ishlatilmaydi**. Yangi qiymat jadvalda **hech qachon bo'lgan** eng katta qiymatdan kamida 1 ga katta bo'ladi. Buning uchun SQLite eng katta qiymatni `sqlite_sequence` jadvalida saqlab boradi.

```sql
CREATE TABLE oddiy (id INTEGER PRIMARY KEY, ism TEXT);
CREATE TABLE auto  (id INTEGER PRIMARY KEY AUTOINCREMENT, ism TEXT);
INSERT INTO oddiy (ism) VALUES ('Ali'), ('Vali'), ('Sobir');
INSERT INTO auto  (ism) VALUES ('Ali'), ('Vali'), ('Sobir');
SELECT last_insert_rowid() AS oxirgi;
DELETE FROM oddiy WHERE id = 3;
DELETE FROM auto  WHERE id = 3;
INSERT INTO oddiy (ism) VALUES ('Yangi');
INSERT INTO auto  (ism) VALUES ('Yangi');
SELECT 'oddiy' AS jadval, id, ism FROM oddiy
UNION ALL
SELECT 'auto', id, ism FROM auto;
SELECT * FROM sqlite_sequence;
```

```text
oxirgi
------
     3
jadval  id   ism
------  --  -----
oddiy    1  Ali
oddiy    2  Vali
oddiy    3  Yangi
auto     1  Ali
auto     2  Vali
auto     4  Yangi
name  seq
----  ---
auto    4
```

- `oddiy` jadvalida eng oxirgi qator o'chirilgandan keyin 3 qayta ishlatildi.
- `auto` jadvalida esa 4 berildi, chunki `sqlite_sequence` 3 ni eslab qolgan edi.

Hujjatdagi muhim nozik jihat: `AUTOINCREMENT` faqat **commit qilingan** tranzaksiyalardagi qiymatlarni hisobga oladi. Bekor qilingan tranzaksiyaning raqami qayta ishlatilishi mumkin:

```sql
CREATE TABLE a (id INTEGER PRIMARY KEY AUTOINCREMENT, x);
INSERT INTO a (x) VALUES (1);
BEGIN;
INSERT INTO a (x) VALUES (2);
ROLLBACK;
INSERT INTO a (x) VALUES (3);
SELECT * FROM a;
```

```text
id  x
--  -
 1  1
 2  3
```

PostgreSQL va MySQL'da shu holatda 2-raqam "yo'qolardi".

`AUTOINCREMENT` faqat `INTEGER PRIMARY KEY` bilan ishlaydi:

```text
SQLite-3.54 memory-> CREATE TABLE xato (id INT PRIMARY KEY AUTOINCREMENT);
Parse error near line 1: AUTOINCREMENT is only allowed on an INTEGER PRIMARY KEY
```

Hujjatga ko'ra tip nomi aynan `INTEGER` bo'lishi kerak. `INT`, `BIGINT`, `UNSIGNED INTEGER` kabi nomlar bilan ustun `rowid` taxallusi emas, butun son affinity'li oddiy ustun va takrorlanmas indeksga aylanadi.

### Qisqacha jadval

| | PostgreSQL | MySQL | SQLite |
| --- | --- | --- | --- |
| Standart yo'l | `GENERATED … AS IDENTITY` | Yo'q | Yo'q |
| Odatiy yo'l | Identity (`serial` — eski) | `AUTO_INCREMENT` | `INTEGER PRIMARY KEY` (`rowid`) |
| Alohida sequence obyekti | `CREATE SEQUENCE` | Yo'q | Yo'q |
| Qo'lda qiymat yozish | `ALWAYS`: faqat `OVERRIDING SYSTEM VALUE`; `BY DEFAULT`: mumkin | Mumkin | Mumkin |
| Qo'lda kattaroq qiymatdan keyin | Sequence o'zgarmaydi → keyin to'qnashuv | Hisoblagich eng katta qiymatga suriladi | Eng katta `rowid` + 1 |
| Oxirgi qiymatni olish | `RETURNING` (19-bob), `currval()` | `LAST_INSERT_ID()` — ko'p qatorlida birinchisi | `last_insert_rowid()` |
| `ROLLBACK` dan keyin | Bo'shliq | Bo'shliq | Raqam qayta ishlatiladi (`AUTOINCREMENT` bilan ham) |
| O'chirilgan oxirgi raqam | Qayta ishlatilmaydi | Qayta ishlatilmaydi | `AUTOINCREMENT` siz — qayta ishlatiladi |
| Yagonalik | `PRIMARY KEY`/`UNIQUE` kerak | Kalit bo'lishi shart | `rowid` — doim yagona |

## Tipik xatolar

| Xato | Nega yomon | To'g'ri yo'l |
| --- | --- | --- |
| Raqamlar bo'shliqsiz bo'ladi deb kutish (hisob-faktura raqami) | `ROLLBACK`, xato, `ON CONFLICT`, `CACHE` bo'shliq qoldiradi | Bo'shliqsiz raqam kerak bo'lsa, alohida hisoblagich va qulf (54-bob) |
| PostgreSQL'da `BY DEFAULT` ustunga qo'lda qiymat yozib qo'yish | Sequence keyinroq shu qiymatga yetib, to'qnashuv beradi | `ALWAYS` ishlatish; ko'chirishdan keyin `setval()` bilan sequence'ni surish |
| Identity ustunni `PRIMARY KEY` siz qoldirish | Takror qiymatlar jimgina yoziladi | `PRIMARY KEY` yoki `UNIQUE` |
| Yangi loyihada `serial` ishlatish | PostgreSQL'ga xos eski usul | `GENERATED ALWAYS AS IDENTITY` |
| Katta jadval uchun `integer` identity | 2 147 483 647 dan keyin to'xtaydi | `bigint` |
| MySQL'da ko'p qatorli `INSERT` dan keyin `LAST_INSERT_ID()` ni oxirgi raqam deb o'ylash | U birinchi yaratilgan qiymat | Birinchisidan boshlab qatorlar sonini qo'shib hisoblash yoki qayta so'rash |
| MySQL'da `AUTO_INCREMENT` ga `TINYINT`/`SMALLINT` tanlash | Tez to'lib qoladi | Kutilgan hajmga yetarli tip, ko'pincha `BIGINT` |
| SQLite'da odat bo'yicha `AUTOINCREMENT` yozish | Qo'shimcha xarajat; odatda kerak emas | `INTEGER PRIMARY KEY` |
| SQLite'da `INT PRIMARY KEY` ni `rowid` taxallusi deb o'ylash | Faqat aynan `INTEGER PRIMARY KEY` taxallus | `INTEGER PRIMARY KEY` |

## Amaliyot

1. PostgreSQL'da `GENERATED ALWAYS AS IDENTITY (START WITH 1000 INCREMENT BY 5)` bilan jadval yarating va uchta qator qo'shing.
2. `BY DEFAULT` jadvalga qo'lda `id = 50` yozing. Keyin `SELECT setval(pg_get_serial_sequence('jadval', 'id'), (SELECT max(id) FROM jadval));` ni bajaring va yangi qator qo'shing. Nima o'zgardi?
3. Ikki `psql` oynasida bitta sequence'dan `nextval` va `currval` ni navbatma-navbat chaqiring. `currval` nega har oynada har xil?
4. `CREATE SEQUENCE s CACHE 10;` yarating. Ikki seansda `nextval('s')` ni chaqiring va qiymatlarni solishtiring. Hujjatdagi `CACHE` haqidagi ogohlantirishni o'qing.
5. MySQL'da `INSERT INTO t (id) VALUES (0)` ni avval odatiy rejimda, keyin `SET sql_mode = CONCAT(@@sql_mode, ',NO_AUTO_VALUE_ON_ZERO')` dan keyin bajaring.
6. SQLite'da `AUTOINCREMENT` li jadvalga 3 ta qator yozing, hammasini o'chiring va yangi qator qo'shing. `sqlite_sequence` ni ko'ring. Xuddi shuni `AUTOINCREMENT` siz takrorlang.
