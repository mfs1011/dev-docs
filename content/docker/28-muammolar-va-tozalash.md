# 28 — Muammolarni topish va tozalash

[← Oldingi: Serverga deploy](27-deploy.md) · [Mundarija](README.md)

## Tushuncha

Kitobning oxirgi bobi — ish jarayonida eng ko'p kerak bo'ladigan ikki ko'nikma: **nima buzilganini topish** va **diskni tozalash**. Asboblarning ko'pini oldingi boblarda ko'rganmiz; bu yerda ularni bir tartibga solamiz.

| Savol | Buyruq |
| --- | --- |
| Konteyner ishlayaptimi, necha marta qayta ishga tushdi? | `docker ps -a`, `docker inspect` |
| Nega yiqildi? | `docker logs` |
| Ichkaridan qanday ko'rinadi (tarmoq, DNS, fayllar)? | `docker exec` |
| Qancha resurs ishlatyapti? | `docker stats` |
| Daemon ishlayaptimi, sozlamasi to'g'rimi? | `docker info`, `systemctl is-active docker`, `dockerd --validate` |
| Disk qayerga ketdi? | `docker system df`, `prune` |

## 1. Konteyner ishga tushmaydi

Nginx sozlamasida xato — `location` o'rniga `lokatsiya`:

```nginx
server {
    listen 80;
    lokatsiya / {
        root /usr/share/nginx/html;
    }
}
```

```text vps
$ docker run -d --name buzuq --restart on-failure:2 -p 127.0.0.1:8090:80 -v ./default.conf:/etc/nginx/conf.d/default.conf:ro nginx:1.29
8388cd7e7714b52a876149e60fd326657ec7c332e9ed0dbc891fc65c65712522
$ sleep 5; docker ps -a --filter name=buzuq --format 'table {{.Names}}\t{{.Status}}'
NAMES     STATUS
buzuq     Exited (1) 2 seconds ago
$ docker logs buzuq 2>&1 | tail -2
2026/11/07 22:38:26 [emerg] 1#1: unknown directive "lokatsiya" in /etc/nginx/conf.d/default.conf:3
nginx: [emerg] unknown directive "lokatsiya" in /etc/nginx/conf.d/default.conf:3
$ docker inspect --format 'status={{.State.Status}} exit={{.State.ExitCode}} restarts={{.RestartCount}} error={{.State.Error}}' buzuq
status=exited exit=1 restarts=2 error=
```

Tartib:

1. `docker ps -a` — `Exited (1)`: jarayon xato kodi bilan chiqdi (137 bo'lsa — o'ldirilgan, 8-, 27-boblar).
2. `docker logs` — sababi: `unknown directive "lokatsiya" … default.conf:3` — fayl va qator raqami bilan.
3. `docker inspect` — `restarts=2`: restart policy ishladi, lekin foydasiz — xato sozlamada. Qayta ishga tushirish sozlama xatosini tuzatmaydi.

Ko'p dasturlarda sozlamani **ishga tushirmasdan tekshirish** buyrug'i bor. Nginx'da — `nginx -t` (rasmiy `nginx` image'ida buyruqni almashtirib, 8-bob):

## 2. Ichkaridan qarash: `docker exec`

Konteyner ishlayapti, lekin "ishlamayapti" — ichkaridan tekshiramiz (27-bobdagi `deploy-web-1`):

```text vps
$ docker exec deploy-web-1 wget -qO- http://127.0.0.1:8080/ | head -c 60; echo
<!doctype html>
<html lang="uz">
  <head><meta charset="UTF-
$ docker exec deploy-web-1 cat /etc/resolv.conf
# Generated by Docker Engine.
# This file can be edited; Docker Engine will not make further changes once it
# has been modified.

nameserver 127.0.0.11
search .
options edns0 trust-ad ndots:0

# Based on host file: '/etc/resolv.conf' (internal resolver)
# ExtServers: [host(127.0.0.53)]
# Overrides: []
# Option ndots from: internal
```

- Servis konteyner ichida javob beryapti — muammo tashqarida (port, proksi, firewall — 5-bob).
- `nameserver 127.0.0.11` — Docker'ning ichki DNS serveri (16-bob).

DNS: konteyner boshqa servisni nomi bilan topadimi?

```text vps
$ docker exec deploy-web-1 nslookup registry 2>&1 | tail -2
** server can't find registry: SERVFAIL

$ docker exec deploy-web-1 nslookup web
Server:		127.0.0.11
Address:	127.0.0.11:53

Non-authoritative answer:

Non-authoritative answer:
Name:	web
Address: 172.19.0.2

```

`registry` topilmadi (`SERVFAIL`), `web` — topildi. Sababi 16-bobda: nom bo'yicha topish faqat **bitta foydalanuvchi tarmog'idagi** konteynerlar orasida ishlaydi. `registry` alohida `docker run` bilan standart `bridge` tarmog'ida, `web` esa Compose'ning `deploy_default` tarmog'ida. "Servis boshqa servisni ko'rmayapti" muammosining eng ko'p uchraydigan sababi shu.

Image'da `nslookup`, `wget` bo'lmasa (distroless, `scratch` — 11-bob) — `docker debug` (Docker Desktop) yoki o'sha tarmoqqa ulangan yordamchi konteyner (`docker run --rm --network <tarmoq> busybox …`).

## 3. Resurslar: `docker stats`

CLI hujjati (`docker container stats`): ishlab turgan konteynerlar uchun jonli ma'lumot oqimi (live data stream); `--no-stream` — bir martalik:

```text vps
$ docker stats --no-stream --format 'table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}\t{{.NetIO}}'
NAME           CPU %     MEM USAGE / LIMIT     NET I/O
deploy-web-1   0.00%     2.668MiB / 64MiB      1.09kB / 126B
registry       0.00%     9.426MiB / 1.751GiB   1.38kB / 126B
```

- `deploy-web-1` — `/ 64MiB`: 27-bobdagi chegara.
- `registry` — `/ 1.751GiB`: chegara yo'q, butun server xotirasi.
- Xotira chegaraga yaqin turgan konteyner — OOM nomzodi (27-bob).

## 4. Daemon

Docker hujjati (Troubleshoot the Docker daemon):

- `Cannot connect to the Docker daemon` — daemon ishlamayapti yoki klient boshqa xostga ulanmoqchi (`DOCKER_HOST` ni tekshiring: `env | grep DOCKER_HOST`).
- Ishlayotganini tekshirish: `docker info` yoki `systemctl is-active docker`.
- Daemon loglari (Linux): `journalctl -xu docker.service` (hujjat: Read the daemon logs).

`daemon.json` daemon sozlamasini o'zgartiradi; hujjat misolida u bilan buyruq qatori flag'lari to'qnashganda Docker **ishga tushmaydi** — daemon bilan birga barcha konteynerlar ham. Shuning uchun o'zgartirishdan oldin tekshiramiz (`dockerd` hujjati: `--validate` — daemon'ni ishga tushirmasdan sozlamani tekshirish, xato bo'lsa nol bo'lmagan kod):

```json
{
  "log-driver": "local",
  "log-opts": { "max-size": "10m" },
  "debag": true
}
```

```text vps
$ systemctl is-active docker
active
$ dockerd --validate --config-file ./daemon-xato.json; echo "kod: $?"
unable to configure the Docker daemon with file ./daemon-xato.json: the following directives don't match any configuration option: debag
kod: 1
$ sed -i 's/debag/debug/' daemon-xato.json; dockerd --validate --config-file ./daemon-xato.json; echo "kod: $?"
configuration OK
kod: 0
```

`debag` — imlo xatosi, `--validate` uni topdi. Tuzatilgandan keyin — `configuration OK`. Faqat shundan keyin faylni `/etc/docker/daemon.json` ga qo'yib, `systemctl restart docker`.

## 5. Disk: `system df` va `prune`

Docker vaqt o'tishi bilan image'lar, to'xtagan konteynerlar, volume'lar va build keshini to'playdi. Docker hujjati (Prune unused Docker objects): Docker tozalashga ehtiyotkor yondashadi — ishlatilmayotgan obyektlar siz so'ramaguningizcha odatda **o'chirilmaydi**; har bir tur uchun `prune` buyrug'i bor.

Shu kitob davomida server qancha yig'di:

```text vps
$ docker system df
TYPE            TOTAL     ACTIVE    SIZE      RECLAIMABLE
Images          48        3         6.105GB   3.51GB (57%)
Containers      3         2         94.21kB   20.48kB (21%)
Local Volumes   11        2         413.4MB   338.4MB (81%)
Build Cache     151       0         4.596GB   1.035GB
$ docker container ls -a --filter status=exited --format '{{.Names}}' | wc -l
1
$ docker image ls --filter dangling=true -q | wc -l
0
$ docker system prune -f | tail -1
Total reclaimed space: 1.035GB
$ docker system df
TYPE            TOTAL     ACTIVE    SIZE      RECLAIMABLE
Images          48        2         6.105GB   4.043GB (66%)
Containers      2         2         73.73kB   0B (0%)
Local Volumes   11        1         413.4MB   387.4MB (93%)
Build Cache     96        0         3.561GB   0B
$ docker volume ls --format '{{.Name}}' | grep -v '^[0-9a-f]\{64\}$'
db_pgdata
stack_pgdata
stack_redisdata
```

- `system df` — tur bo'yicha hajm va `RECLAIMABLE` (bo'shatish mumkin bo'lgani).
- `docker system prune` (hujjat): to'xtagan konteynerlar, ishlatilmayotgan tarmoqlar, osilib qolgan (dangling) image'lar va ishlatilmayotgan build keshi. **Volume'lar o'chirilmaydi** (`--volumes` — faqat anonim volume'lar).
- Bo'shadi 1.035GB — asosan build keshi.
- To'xtagan konteyner (`db-db-1`, 27-bobdagi daemon qayta ishga tushganidan beri `Exited`) o'chdi, lekin uning **nomli volume'i** `db_pgdata` — joyida: ma'lumot saqlanadi (6-, 24-boblar).

Ko'proq joy — ishlatilmayotgan **barcha** image'lar va butun build keshi:

```text vps
$ docker image prune -a -f | tail -1
Total reclaimed space: 5.235GB
$ docker builder prune -a -f | tail -1
Total:	3.561GB
$ docker system df
TYPE            TOTAL     ACTIVE    SIZE      RECLAIMABLE
Images          2         2         178.3MB   0B (0%)
Containers      2         2         73.73kB   0B (0%)
Local Volumes   11        1         413.4MB   387.4MB (93%)
Build Cache     0         0         0B        0B
$ docker image ls --format '{{.Repository}}:{{.Tag}}'
localhost:5000/spa:1.0.0
registry:3
```

- `image prune -a` — hujjat: konteyneri yo'q **barcha** image'lar (oddiy `image prune` — faqat dangling'lar). 5.2GB bo'shadi; faqat ishlayotgan konteynerlarning ikki image'i qoldi.
- `builder prune -a` — build keshi to'liq.
- Narxi: keyingi `docker run postgres:18` yoki build image'larni qayta yuklaydi va keshsiz yig'adi (9-bob).

Hujjatdagi ehtiyot vositalari:

| Buyruq | Nima qiladi |
| --- | --- |
| `docker image prune -a --filter "until=24h"` | Faqat 24 soatdan eski image'lar |
| `docker container prune --filter "until=24h"` | Faqat 24 soatdan avval to'xtaganlar |
| `docker volume prune` | Faqat **anonim** ishlatilmayotgan volume'lar |
| `docker volume prune --all` | Nomli volume'lar ham — **ma'lumot yo'qoladi**, ehtiyot bo'ling |

## Tipik xatolar

**1. Konteyner yiqilganda faqat qayta ishga tushirish.**
Sozlama xatosi restart bilan tuzalmaydi (`restarts=2`, natija bir xil).
To'g'risi: avval `docker logs`.

**2. Konteynerlar bir-birini "ko'rmayapti" — IP manzil bilan ulanish.**
To'g'risi: bitta foydalanuvchi tarmog'i va servis nomi (16-bob).

**3. `daemon.json` ni tekshirmasdan o'zgartirish.**
Daemon ishga tushmasa, serverdagi barcha servislar to'xtaydi.
To'g'risi: `dockerd --validate --config-file …`.

**4. `docker volume prune --all` ni "tozalash" uchun ishlatish.**
Nomli volume'lardagi bazalar o'chadi.
To'g'risi: avval `docker volume ls`, zaxira (24-bob); odatda `system prune` yetarli.

**5. Diskni hech qachon tozalamaslik.**
Build keshi va eski image'lar gigabaytlab yig'iladi (bizda — 6GB+).
To'g'risi: davriy `docker system df` va `prune`.
