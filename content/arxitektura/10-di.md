# 10 — Bog'liqlikni teskari qilish va DI

[← Oldingi: Kompozitsiya va meros](09-kompozitsiya.md) · [Mundarija](README.md) · [Keyingi: Modulning ochiq API'si →](11-ochiq-api.md)

## Tushuncha

Uch tushuncha tez-tez aralashadi:

| Tushuncha | Nima | Daraja |
| --- | --- | --- |
| **Dependency Inversion** (SOLID "D") | Biznes abstraksiyaga tayansin, abstraksiya egasi — biznes | Dizayn tamoyili |
| **Dependency Injection** | Qaramlik tashqaridan beriladi, ob'ekt o'zi yaratmaydi | Texnika |
| **DI konteyner** | Qaramliklarni avtomatik yig'uvchi vosita | Vosita |

DI konteynersiz ham DI mumkin — oddiy konstruktor argumenti. Konteyner — faqat katta tizimda ulash kodini avtomatlashtirish.

## Nega shunday

```text
class ReportService:
    generate():
        db = new MysqlConnection(env("DB_URL"))       // 1. qattiq bog'lanish
        clock = system.now()                           // 2. testda vaqtni boshqarib bo'lmaydi
        mailer = new SmtpMailer()                      // 3. testda haqiqiy email ketadi
```

Muammolar:
- **Test:** haqiqiy DB, haqiqiy vaqt, haqiqiy email — test sekin, beqaror, xavfli.
- **Almashtirish:** MySQL → PostgreSQL yoki SMTP → API — klassni tahrirlash.
- **Yashirin bog'liqlik:** klass imzosidan uning nimaga muhtojligi ko'rinmaydi.

## Psevdokod: qo'lda DI

```text
class ReportService(db: Database, clock: Clock, mailer: Mailer):
    generate():
        rows = db.query(...)
        report = build(rows, clock.now())
        mailer.send(report)

// Ishlab chiqarishda — "kompozitsiya ildizi" (composition root): bitta joyda ulash
main():
    db = PostgresDatabase(config.dbUrl)
    service = ReportService(db, SystemClock(), SmtpMailer(config.smtp))

// Testda
test():
    service = ReportService(InMemoryDatabase(fixtures), FixedClock("2026-01-01"), FakeMailer())
```

**Composition root** — ilovaning kirish nuqtasi (`main`, bootstrap, konteyner konfiguratsiyasi). Faqat u konkret klasslarni biladi. Qolgan kod — faqat abstraksiyalarni.

## Psevdokod: konteyner nima qo'shadi

```text
container.bind(Database, PostgresDatabase).singleton()
container.bind(Clock, SystemClock)
container.bind(Mailer, SmtpMailer)
service = container.get(ReportService)     // konstruktor imzosidan avtomatik yig'adi
```

| Konteyner imkoniyati | Foyda |
| --- | --- |
| Autowiring | 100 ta xizmatni qo'lda ulash kerak emas |
| Umr boshqaruvi (singleton / har so'rov / har chaqiruv) | Ulanishlar, kesh — to'g'ri umr |
| Dekoratsiya, tagged xizmatlar | O/C tamoyili (8-bob) framework darajasida |
| Kechiktirilgan yaratish (lazy) | Ishga tushish tezligi |

## Psevdokod: umr (scope) — eng ko'p xato qilinadigan joy

```text
singleton     — ilova davomida bitta:     DB pool, konfiguratsiya, kesh klienti
scoped        — har so'rovga bitta:        joriy foydalanuvchi, tranzaksiya, request context
transient     — har inject'ga yangi:       yengil, holatsiz yordamchilar

XATO: singleton ichida scoped qaramlik
  class ReportService(currentUser: CurrentUser)   // ReportService singleton
  // birinchi so'rov foydalanuvchisi — hamma keyingi so'rovlarda! Ma'lumot sizishi.
```

Bu xato ayniqsa uzoq yashaydigan jarayonlarda xavfli: PHP-FPM har so'rovda qayta boshlaydi (ko'pincha yashirinadi), lekin RoadRunner, Swoole, Laravel Octane, FrankenPHP worker rejimi, Node.js SSR serverida — singleton'dagi foydalanuvchi ma'lumoti **boshqa foydalanuvchiga** ko'rinadi.

## Framework'larda

| Framework | DI shakli | Nozik joy | Qayerda |
| --- | --- | --- | --- |
| Symfony | Konteyner kompilyatsiyada, autowiring, atributlar | Xizmatlar sukut bo'yicha shared (singleton) | [Symfony 5](../symfony/05-service-container.md), [6-bob](../symfony/06-container-chuqur.md) |
| Laravel | Service container, provider'lar | `singleton` vs `bind`, Octane'da holat | [Laravel 5](../laravel/05-service-container.md), [6-bob](../laravel/06-service-provider.md) |
| Angular | Ierarxik injectorlar, `inject()`, `@Service()` | Komponent `providers` — yangi nusxa; SSR'da modul darajasidagi o'zgaruvchilar umumiy | [Angular 34–39-boblar](../angular/34-di-modeli.md), [62-bob](../angular/62-ssr-asoslari.md) |
| Vue | `provide/inject` — komponent daraxti bo'ylab | Reaktivlikni saqlash uchun `ref` berish | [Vue 27-bob](../vue/27-provide-inject.md) |
| React | Konteyner yo'q; Context + props, modul importlari | Context qiymati o'zgarsa — barcha iste'molchilar qayta render | [React 20-bob](../react/20-context.md) |

Angular'da tekshirilgan misol ([37-bob](../angular/37-injector-iyerarxiyasi.md)): global `@Service() Cart` ni tasodifan komponent `providers` ga qo'shish — **ikkinchi nusxa** yaratadi, savat "bo'linadi". Bu — umr (scope) xatosining frontend ko'rinishi.

## Trade-off

| Yondashuv | Yutuq | Narx |
| --- | --- | --- |
| `new` ichkarida | Oddiy, aniq | Test va almashtirish qiyin |
| Qo'lda DI (konstruktor) | Aniq, sehr yo'q, har tilda | Katta tizimda ulash kodi ko'p |
| Konteyner + autowiring | Kam kod, umr boshqaruvi | "Sehr": xato kech (ish vaqtida) chiqishi mumkin, qaramlik grafi ko'rinmaydi |
| Service locator (`container.get()` ichkarida) | Tez | Yashirin bog'liqlik — anti-naqsh |

## Tipik xatolar

| Xato | Nega yomon | To'g'ri yo'l |
| --- | --- | --- |
| Biznes kodida `container.get(X)` | Service locator — yashirin qaramlik | Konstruktor/`inject()` maydonda |
| Singleton'da so'rovga xos holat | Foydalanuvchilar o'rtasida ma'lumot sizishi | Scoped umr yoki argument sifatida |
| Hamma narsa interfeys + konteyner | Ortiqcha marosim (6-bob) | Almashtirish/test ehtiyoji bo'lsa |
| Vaqt, tasodif, UUID'ni to'g'ridan-to'g'ri | Test qilib bo'lmaydi | `Clock`, `IdGenerator` qaramlik |
| 10+ konstruktor argumenti | Klass juda ko'p ish qiladi | S tamoyili — bo'lish (8-bob) |

## Amaliyot

1. Loyihangizda `new` bilan yaratilayotgan infratuzilma (DB, HTTP, mailer) ni biznes kodida qidiring.
2. Vaqtga bog'liq bitta qoidani (`now()`) `Clock` qaramligiga o'tkazib, test yozing.
3. Singleton xizmatlarda so'rovga xos maydon bormi — tekshiring (ayniqsa Octane/SSR bo'lsa).
4. Composition root'ingiz qayerda — bitta joydami yoki tarqalganmi?
