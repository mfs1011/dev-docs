## Tushuncha

E2E (end-to-end) test — haqiqiy brauzerda, haqiqiy build'da foydalanuvchi oqimini boshidan oxirigacha tekshirish: "kirdim → mahsulot qidirdim → savatga qo'shdim → to'ladim".

Angular CLI'da `ng e2e` buyrug'i bor, lekin sukut bo'yicha sozlanmagan. Tekshirildi — yangi loyihada:

```
Cannot find "e2e" target for the specified project.
You can add a package that implements these capabilities.
  Playwright: ng add playwright-ng-schematics
  Cypress: ng add @cypress/schematic
  ...
```

Hozirgi standart — **Playwright**:

```bash
npm init playwright@latest          # yoki: ng add playwright-ng-schematics (ng e2e bilan)
```

| Afzallik | |
| --- | --- |
| Chromium, Firefox, WebKit | Uchta dvigatelda bir xil test |
| Avtomatik kutish | `click` element tayyor bo'lishini kutadi — `sleep` kerak emas |
| Tarmoqni boshqarish | `page.route` bilan API mock |
| Trace viewer | Yiqilgan testning har qadami, DOM, tarmoq |

## Nega shunday

Birlik va komponent testlari qismlarni tekshiradi; E2E — ular **birga** ishlashini: marshrutlar, guardlar, interceptorlar, SSR, hydration, haqiqiy CSS (tugma boshqa element ostida qolmaganmi). Lekin E2E sekin va mo'rt — shuning uchun **kam**: faqat pul keltiradigan va eng muhim oqimlar.

## Kod: sozlash

```ts
// playwright.config.ts
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  testDir: './e2e',
  fullyParallel: true,
  retries: process.env['CI'] ? 2 : 0,
  reporter: process.env['CI'] ? 'github' : 'list',
  use: {
    baseURL: 'http://localhost:4200',
    trace: 'on-first-retry',
  },
  projects: [
    { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
    { name: 'mobile', use: { ...devices['Pixel 7'] } },
  ],
  webServer: {
    command: 'npm run start',
    url: 'http://localhost:4200',
    reuseExistingServer: !process.env['CI'],
  },
});
```

`webServer` — test boshlanishidan oldin ilovani ishga tushiradi. SSR ilova uchun — `npm run build && npm run serve:ssr:shop` va mos port.

## Kod: test

```ts
// e2e/home.spec.ts
import { test, expect } from '@playwright/test';

test('bosh sahifa: tugma hisoblagichi', async ({ page }) => {
  await page.goto('/');
  await expect(page.getByRole('heading', { name: 'Bosh' })).toBeVisible();

  const btn = page.getByRole('button', { name: /bos/ });
  await btn.click();
  await btn.click();
  await expect(btn).toHaveText('bos 2');
});

test('404 sahifa', async ({ page }) => {
  const res = await page.goto('/yoq-sahifa');
  expect(res?.status()).toBe(404);
  await expect(page.getByRole('heading', { name: 'Topilmadi' })).toBeVisible();
});
```

Tekshirildi — 63-bobdagi SSR ilovaga qarshi: 3 ta test o'tdi. 404 testi server marshrutidagi `status: 404` ni haqiqiy HTTP darajasida tekshiradi — birlik testi buni qila olmaydi.

### Lokatorlar — foydalanuvchi kabi

| Lokator | Qachon |
| --- | --- |
| `getByRole('button', { name: 'Saqlash' })` | **Birinchi tanlov** — erishimlilik ham tekshiriladi |
| `getByLabel('Email')` | Forma maydonlari |
| `getByText('Savat bo\'sh')` | Matn |
| `getByTestId('order-total')` | Boshqasi mos kelmasa (`data-testid`) |
| `locator('.btn-primary > span')` | ❌ Deyarli hech qachon — CSS o'zgarsa buziladi |

`getByRole` topolmasa — ko'pincha erishimlilik muammosi: tugma `<div>`, label yo'q. Test sizga bepul a11y tekshiruvi beradi.

`expect(locator).toHaveText(...)` — **avtomatik qayta urinadi** (sukut 5 s). `expect(await locator.textContent()).toBe(...)` — urinmaydi, zoneless'da CD ulgurmasligi mumkin (64-bobda shunday holat kuzatilgan).

## Kod: login holatini qayta ishlatish

Har testda login qilish — sekin. Bir marta kirib, holatni saqlash:

```ts
// e2e/auth.setup.ts
import { test as setup, expect } from '@playwright/test';

setup('login', async ({ page }) => {
  await page.goto('/login');
  await page.getByLabel('Email').fill('test@example.uz');
  await page.getByLabel('Parol').fill(process.env['E2E_PASSWORD']!);
  await page.getByRole('button', { name: 'Kirish' }).click();
  await expect(page.getByRole('heading', { name: 'Kabinet' })).toBeVisible();
  await page.context().storageState({ path: 'e2e/.auth/user.json' });
});
```

```ts
// playwright.config.ts
projects: [
  { name: 'setup', testMatch: /.*\.setup\.ts/ },
  { name: 'chromium', use: { ...devices['Desktop Chrome'], storageState: 'e2e/.auth/user.json' }, dependencies: ['setup'] },
],
```

`e2e/.auth/` — `.gitignore` da. Parol — muhit o'zgaruvchisida, kodda emas.

## Kod: API mock

```ts
test('bo\'sh savat holati', async ({ page }) => {
  await page.route('**/api/cart', (route) => route.fulfill({ json: { items: [] } }));
  await page.goto('/cart');
  await expect(page.getByText("Savat bo'sh")).toBeVisible();
});

test('server xatosi', async ({ page }) => {
  await page.route('**/api/products**', (route) => route.fulfill({ status: 500, json: { message: 'x' } }));
  await page.goto('/products');
  await expect(page.getByRole('alert')).toContainText('Serverda xatolik');
});
```

**SSR tuzog'i** (tekshirildi): `page.route` faqat **brauzer** so'rovlarini ushlaydi. SSR sahifada ma'lumot **serverda** olinadi, transfer cache bilan brauzer qayta so'ramaydi — mock ta'sir qilmaydi (sahifada haqiqiy server javobi ko'rindi). SSR sahifalar uchun: test backend (staging API), yoki mock'ni brauzer navigatsiyasi bilan (boshqa sahifadan `routerLink` orqali o'tish — CSR navigatsiya), yoki Client rejimdagi marshrut.

## Kod: CI

```yaml
# .github/workflows/e2e.yml
name: e2e
on: [pull_request]
jobs:
  e2e:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: npm ci
      - run: npx playwright install --with-deps chromium
      - run: npx playwright test
        env:
          E2E_PASSWORD: ${{ secrets.E2E_PASSWORD }}
      - uses: actions/upload-artifact@v4
        if: failure()
        with: { name: playwright-report, path: playwright-report }
```

Yiqilgan testning trace'i: `npx playwright show-trace trace.zip` — har qadam, DOM snapshot, tarmoq, konsol.

## Kod: erishimlilik tekshiruvi

```bash
npm i -D @axe-core/playwright
```

```ts
import AxeBuilder from '@axe-core/playwright';

test('bosh sahifada a11y xatosi yo\'q', async ({ page }) => {
  await page.goto('/');
  const results = await new AxeBuilder({ page }).analyze();
  expect(results.violations).toEqual([]);
});
```

Avtomatik tekshiruv muammolarning ~30–40% ini topadi (kontrast, label, rol) — qolgani qo'lda (75-bob).

## Muhandislik nuqtai nazari

**Qaysi oqimlar E2E'ga:**

| Ha | Yo'q |
| --- | --- |
| Ro'yxatdan o'tish, login | Har validatsiya xabari (komponent testi) |
| Checkout, to'lov | Har filtr kombinatsiyasi |
| Asosiy qidiruv | Narx formulasi (birlik testi) |
| Rol bo'yicha ruxsat (admin/foydalanuvchi) | Stil tafsilotlari |

5–20 ta ishonchli E2E test > 200 ta "ba'zan yiqiladigan". **Flaky** (beqaror) test — darhol tuzatish yoki o'chirish: jamoa yiqilgan testlarga e'tibor bermaslikni o'rganib qoladi.

## Tipik xatolar

| Xato | Oqibat | To'g'ri yo'l |
| --- | --- | --- |
| `page.waitForTimeout(2000)` | Sekin va baribir beqaror | Avtomatik kutuvchi `expect(...).toHaveText` |
| CSS selektorlar | Dizayn o'zgarsa buziladi | `getByRole`, `getByLabel` |
| `expect(await el.textContent())` | Qayta urinmaydi | `await expect(el).toHaveText()` |
| Har testda login | Sekin | `storageState` |
| SSR sahifada `page.route` mock | Ta'sir qilmaydi | Test backend / CSR navigatsiya |
| Testlar bir-biriga bog'liq | Tartib o'zgarsa yiqiladi | Har test mustaqil ma'lumot |
| Parol kodda | Sizib chiqish | CI secrets |

## Amaliyot

1. `npm init playwright@latest` — `webServer` bilan sozlang.
2. Bosh sahifa va 404 testlari (yuqoridagi).
3. Login `setup` loyihasi va `storageState`.
4. `page.route` bilan bo'sh savat va server xatosi holatlari (CSR sahifada).
5. SSR sahifada mock ishlamasligini o'zingiz takrorlang.
6. GitHub Actions workflow + `@axe-core/playwright` tekshiruvi.
